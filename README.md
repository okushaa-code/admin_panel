# INaRa админ самбар

INaRa үл хөдлөх хөрөнгийн ажилтнуудад зориулсан Монгол хэл дээрх админ самбар.
Flask + Jinja template + цэвэр CSS; өгөгдлийг Supabase REST API-аар (сервер талаас) уншиж, бичнэ.

## Боломжууд

| Хэсэг | Хийж болох зүйл |
|---|---|
| Нэвтрэх / гарах | `users` хүснэгтийн bcrypt хэшээр сервер талд шалгана. 15 минутад 5 удаа буруу оролдвол түр хаагдана. |
| Профайл | Одоогийн нууц үгийг баталгаажуулж солих (8+ тэмдэгт, үсэг ба тоо, ≤72 байт, хуучнаасаа өөр). |
| Нүүр | Ноорог нийтлэл, цаг товлолт, худалдах/түрээсийн байр, уншаагүй зурвасын тоо; цаг товлолтын төлөв. |
| Худалдаа / Түрээс | Байр нэмэх, засах, устгах (баталгаажуулалттай), нэр/байршил/тайлбараар хайх. |
| Цаг товлолт | Төлөвөөр шүүх; зөвхөн “Хүлээгдэж буй” хүсэлтийг батлах/татгалзах. Шийдвэрлэсэн хүсэлт өөрчлөгдөхгүй. |
| Зурвас | Шинэ нь эхэндээ; төлөвөөр шүүх; уншсан болгох, архивлах, устгах (баталгаажуулалттай). |
| Контент | Ноорог нийтлэлийн жагсаалт (зөвхөн харах). |
| Facebook | **Хэрэгжээгүй.** API интеграц байхгүй; самбарт тодорхой тэмдэглэсэн. |

## Суулгах, ажиллуулах

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # дараа нь утгуудыг бөглөнө
python3 app.py            # http://127.0.0.1:5001
```

### Орчны хувьсагч (`.env`)

| Нэр | Тайлбар |
|---|---|
| `SUPABASE_URL` | Supabase төслийн хаяг. |
| `SUPABASE_SECRET_KEY` | Сервер талын нууц (service-role) түлхүүр. Зөвхөн серверт хадгална. |
| `APP_SECRET_KEY` | Session гарын үсгийн түлхүүр. Байхгүй бол сервер дахин асах бүрт бүх хэрэглэгч гарна. |
| `SESSION_COOKIE_SECURE` | HTTPS дээр `1`. Локал `http://`-д `0`. |
| `PORT` | Заавал биш, анхдагч `5001`. |

`.env` файл `.gitignore`-д орсон — git-д бүү оруул.

## Өгөгдлийн сан

`supabase.sql`-ийг Supabase → **SQL Editor**-т бүтнээр нь хуулж ажиллуулна. Файл давтан ажиллуулахад аюулгүй
(`IF NOT EXISTS`, `ON CONFLICT DO NOTHING`, нөхцөлтэй constraint). Үүнд:

- 6 хүснэгт, жишээ өгөгдөл, `bookings.status` багана;
- `bookings.status`-ийн CHECK хязгаарлалт (`NOT VALID` — хуучин мөрийг шалгахгүй);
- огноо, төлөвийн индексүүд;
- бүх хүснэгтэд RLS идэвхтэй, `users` хүснэгтээс `anon`/`authenticated` эрхийг хассан.

**RLS ба түлхүүр:** RLS асаалттай, policy байхгүй тул браузерын (anon) түлхүүрээр ямар ч өгөгдөл уншигдахгүй.
Самбар service-role түлхүүрийг зөвхөн сервер талд ашигладаг тул RLS-ийг тойрч ажиллана; түлхүүр HTML, лог, алдааны
мэдэгдэлд хэзээ ч гардаггүй.

**Шинэ ажилтан нэмэх:** и-мэйлийг **жижиг үсгээр** хадгална (нэвтрэхэд жижиг үсэг рүү хөрвүүлж хайдаг).

```bash
python3 -c "import bcrypt, getpass; print(bcrypt.hashpw(getpass.getpass().encode(), bcrypt.gensalt(12)).decode())"
```

Гарсан хэшээр SQL Editor-т:

```sql
INSERT INTO public.users (id, email, password_hash)
VALUES (2, 'ajiltan@inara.mn', '<хэш>');
```

## Хамгаалалт

- Бүх POST хүсэлт CSRF токентой; session cookie нь `HttpOnly`, `SameSite=Lax`, 8 цагийн хугацаатай.
- Нэвтрээгүй үед бүх хуудас, үйлдэл нэвтрэх хуудас руу шилжинэ.
- Оролтыг сервер талд шалгадаг (үнэ: 1…bigint, талбай: 0.01…99 999 999.99, өрөө: 0–30, урт хязгаар).
- Jinja автомат escape; CSP (`script-src 'none'`), `X-Frame-Options: DENY`, `nosniff`, `Cache-Control: no-store`.
- Supabase-ийн алдааг зөвхөн HTTP статус ба кодоор логлоно — и-мэйл, түлхүүр, хүсэлтийн бие логт орохгүй.
- Нэвтрэх оролдлогын хязгаар нь процессын санах ойд хадгалагдана (нэг процесстой ажиллуулахад зориулсан).
